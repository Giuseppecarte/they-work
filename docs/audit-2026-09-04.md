# Runtime audit — 2026-09-04

The three things I would fix first:

1. **Restore project grouping under the documented Docker mounts.** A readable Codex store becomes a non-project office when the host project directories are outside the container. This defeats the main view even with valid data.
2. **Ship a runtime with a UTF-8 locale.** The published default demonstrably selects only half blocks; a local screenshot does not verify what a new user receives.
3. **Escape untrusted terminal text at every output boundary.** A transcript can emit an OSC terminal command through both the plain-text report and the interactive desk.

The next priority is the zero-write claim: opening a database read-only still created and wrote SQLite shared-memory files in the native execution test.

## Execution coverage and measured limits

- Malformed/truncated JSONL and invalid UTF-8: checked, found no crash. They silently produce an empty successful `--once`; no claim that the bad records were parsed.
- A 40 MiB command in one JSONL record followed by a small valid record: checked, found no crash; the following `RECOVERED` detail appeared. This verifies bounded skip/recovery, not preservation of oversized content.
- Claude leaf symlinks, FIFOs and non-JSONL files: checked, found nothing.
- Missing stores and corrupt SQLite: checked, found no crash; incomplete-store misdiagnosis is finding 8.
- A live synthetic WAL writer with existing sidecars: both `--doctor` and `--once` read successfully under a read-only mount. Lock contention and long-running concurrent rewrite recovery were not exhaustively tested.
- Config opt-in: `--project ... --config-dir ... --once` left only `project`; an unavailable config directory exited one. No hidden fallback was observed. Interruption during rename/fsync was not forced.
- Capability silence and one garbage reply: checked, found no hang; `q` restored termios. A 160×48 to 40×12 resize also exited cleanly. This does not cover a continuous resize storm or malicious unbounded geometry responses.
- Kitty/Sixel capability replies: image packets emitted. A transmitted packet is not a human visual acceptance test. iTerm2 release difference is finding 6.
- CLI: executed `--help`, `--once`, `--doctor`, `--project`, `--all`, `--demo`, `--headless`, `--exit-after`, all three `--view` values, light/dark, all documented color values, and config opt-in. Invalid view, conflicting once/doctor, and unbounded headless exited two. Headless flag acceptance does not verify the appearance of every view.
- In a disposable copy: `make check` completed with 151 tests passed and one ignored, including format and strict Clippy. `python3 scripts/test-install.py` completed successfully. These passes do not invalidate the runtime findings.
- `make shot` initially failed because the shell sandbox blocked Chromium's `setsockopt`; rerunning outside that shell sandbox succeeded and exported four surfaces in three encodings. This environmental failure is not ranked as a product defect. Generating those files is not a completed human visual review.
- Destructive/document-maintenance commands such as `make clean`, golden regeneration, release tagging/pushing, and editing commands were not executed against the repository. No new clone or publication was needed to test this checkout. In the copied checkout, `make demo` exited zero after `q`; `make run` with empty synthetic homes showed first-run guidance and exited zero after `q`. The first harness attempt waited only for an alternate-screen marker and timed out on that guidance screen; the audit-owned container was removed and the harness was corrected to recognize the first-run quit prompt. This harness mistake is not a product finding.

## Appendix — standalone reproduction harness

Run from a local Docker host with Linux/amd64 support. All fixtures and captures live in a new temporary directory. No agent home is mounted. The Python helper uses a writable scratch mount intentionally so that the executable's own zero-write promise can be tested; the separate cold-ro command above tests the fully protected runtime.

```sh
AUDIT_DIR=$(mktemp -d)
IMAGE=ghcr.io/giuseppecarte/they-work@sha256:b8bf5a70b41ceafcc3331fd790c411e3fd808d3541074dff75ec36858f8ba214
docker pull "$IMAGE"
docker run --rm --network none --read-only --entrypoint /bin/cat \
  "$IMAGE" /usr/local/bin/they-work > "$AUDIT_DIR/published"
chmod +x "$AUDIT_DIR/published"
cat > "$AUDIT_DIR/repro.py" <<'PY_REPRO'
import re,os,sys,json,sqlite3,pathlib,subprocess,pty,fcntl,termios,struct,select,time,signal,shutil
R=pathlib.Path('/audit'); B=str(R/os.environ.get('AUDIT_BINARY','published')); D=R/'fixtures';D.mkdir(exist_ok=True)
PROJECT=D/'project';(PROJECT/'.git').mkdir(parents=True,exist_ok=True)
OSC=b'\x1b]0;AUDIT_TITLE\x07'
def env(claude='absent',codex='absent'):
 e=dict(os.environ);e.update(HOME='/absent',THEYWORK_CLAUDE_HOME=str(D/claude),THEYWORK_CODEX_HOME=str(D/codex),TERM='xterm-256color',LANG='C.UTF-8',LC_ALL='C.UTF-8',LC_CTYPE='C.UTF-8');return e
def cli(args,e):return subprocess.run([B]+args,env=e,capture_output=True,timeout=15)
def row(text='hello',title='Audit'):
 return {'type':'assistant','sessionId':'audit','cwd':str(PROJECT),'customTitle':title,'timestamp':time.strftime('%Y-%m-%dT%H:%M:%SZ',time.gmtime()),'message':{'content':[{'type':'tool_use','id':'one','name':'Bash','input':{'command':text}}]}}
def transcript(name,content):
 p=D/name/'projects/demo/audit.jsonl';p.parent.mkdir(parents=True,exist_ok=True);p.write_bytes(content);return p
def make_db(name,wal=False):
 d=D/name/'sqlite';d.mkdir(parents=True,exist_ok=True)
 s=sqlite3.connect(d/'state_5.sqlite');h=sqlite3.connect(d/'thread_history_1.sqlite')
 if wal:
  for c in (s,h):c.execute('PRAGMA journal_mode=WAL');c.execute('PRAGMA wal_autocheckpoint=0')
 s.execute('CREATE TABLE threads(id TEXT,cwd TEXT,title TEXT,tokens_used INTEGER,git_branch TEXT,updated_at INTEGER,archived INTEGER)')
 s.execute('INSERT INTO threads VALUES(?,?,?,?,?,?,0)',('audit',str(PROJECT),'Audit',0,'main',int(time.time())));s.commit()
```
